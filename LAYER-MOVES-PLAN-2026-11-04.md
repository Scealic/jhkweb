# Layer moves plan - 2026-11-04

Round 2 of the layer analysis. It covers all six Major Version 5 layer repos: 1088 source files in 16 scopes, plus a cross-repo duplication scope. One finder per scope classified every file, an adversarial reviewer tried to refute each proposed move, and the whole-file moves were compile-probed in scratch copies of their target layers (52 agents). Under the user's 2026-11-04 rule, code inside views, view models and models that is not presentation may move down. Most of this round's findings come from that rule. Nothing has changed in the repos yet.

## Decisions needed

1. **Round size.** 254 moves touch every layer. Round 1 had 5. Recommendation: split them in two.
   - **Round 2a:** Kelly-Windows-Data, Kelly-Windows and Kelly-Domain (#1 to #90), plus the rule-1 fixes #94 to #96 and #156 that move code up into Logic (decision 3). Then repin Logic and UI and rebuild Kelly-Revit.
   - **Round 2b:** Kelly-Revit-Logic, Kelly-Revit-UI and Kelly-Revit (#91 to #254), after the user has used 2a in Revit.

   Each round runs the full chain: pack, repin, the 21 Kelly-Revit configurations and the in-Revit tests (about 30 minutes for Logic).
2. **`DataFileService` to Kelly-Domain** (#34, the only high-risk move). The probe failed as a whole file: it needs `#if REVIT20xx` for the Revit version and Logic's `GetForgeTypeId`. Moving it means:
   - a new constructor that takes both, with a Logic factory;
   - a public type moved, which is breaking;
   - rewording the `GetCache` error text "populated during Revit startup", because Domain must name no Revit behaviour. That changes a message.

   Recommendation: **defer**. Backlog it in Kelly-Revit-Logic-v5.
3. **Rule-1 fixes that move code up, out of Kelly-Windows and Kelly-Domain** (breaking public API in the lower layer):
   - #94 `ObjectExtensions.WriteToLog`: it skips properties declared on a type named "FamilyInstance";
   - #95 and #96, both `ToLogDevelopment` overloads: they hard-code `C:\Projects\Revit\Application`;
   - #156 `OperationServiceLogRecord`: it has an `IsRevitTransaction` member.

   All of their callers are Revit-side. The .jsonl log keeps its property names, so stored logs still read. Recommendation: **accept**. Kelly-Windows-v2 (v4) has its own copies and is not touched.
4. **#9 `AddInServices` from Logic `Common` to Kelly-Windows `Hosting`.** Its 13 consumers change namespace, and the type move is breaking. It uses only `ServiceProvider` and `IApplicationService`, and the probe compiled it in Net481 and Net80. The XML crefs to Logic types become plain text. Recommendation: **accept**.

Other medium-risk groups, accepted as the reviewers modified them:
- **The assigner combo-box members into Kelly-Revit-UI `Ribbon`.** One shared base replaces six near-identical copies. The persisted combo names and the event wiring stay the same.
- **The Spool Manager and Module Manage transactions into Logic `Spools`.** Each keeps its transaction name, order and messages. The view model keeps the `UserPrompt` orchestration.
- **`LayoutPointCsvFormat`:** only the header rules move to Domain, as a pure `IsAcceptedHeader(string[])`. The CSV file read stays in Logic as `LayoutPointTools.HasAcceptedHeader(path)`, because Kelly-Domain must not take the CSV library (it has no Net100 package).
- **`DataStore.ReadChecked`** becomes `DataDirectory.ReadAllVerified<T>(manifest)` in Kelly-Windows-Data. Its three messages stay word for word.

## Kept on purpose

1110 files and members were kept, each with a reason (in the scratchpad's `analysis.json`). The notable ones:
- **The host stays where it is:** `App.cs`, `EventService`, `RibbonService` and `ApplicationSessionService`. They need assembly identity, host statics and the startup registrations.
- **Every IExternalCommand, push button and availability leaf class stays in its module.** Only the rule inside an availability class moves, to a Kelly-Revit-UI base or a Logic predicate.
- **The Arrange tools keep their `UIDocument.Selection` handling.** Their database work is already `AnnotationArranger` in Logic.
- **The Developer diagnostics stay** (WindowMockup, AvailabilityProbe). Only their duplicated `ValidateRequirements` and the product-code query move.

Bugs found and noted, not fixed:
- `DocumentOpenedEventHandler` uses `TaskDialog` directly, and its message says "(List set to clipboard...)", but nothing sets the clipboard.
- Both `View*EventHandler` `IsSameDocument` results go into empty `if` bodies.
- `App.OnStartup` shows `TaskDialog` directly after `UserPrompt` is registered.
- `DocumentChangedEventHandler` has two unused `*_Sandbox` methods.
