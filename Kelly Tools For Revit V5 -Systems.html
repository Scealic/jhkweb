Systems Map

2Startup

App (Kelly-Revit-v5/src/App.cs) is the IExternalApplication. Its constructor sets up Serilog (LoggerServices, the "Application Logger", old log files deleted). OnStartup then runs, in order:

  1. RibbonHost.Initialize stores the UIControlledApplication for the ribbon code and the modules.
  2. AddInId is built from a fixed GUID prefix plus the Revit year.
  3. The process-wide seams are registered, before anything uses them.
  4. DataFileLoader.Load with a new DataFileService loads the CSV data files from C:\Program Files\JH Kelly\Kelly Tools For Revit\Data. fails startup with "Kelly Tools For Revit Data Error".
  5. The application services start through ServiceProvider.AddServices. fails startup with "Application Service Start Error".
  6. Telerik assemblies load and the Telerik licence registers. fails startup
  7. Application, Revit and referenced-assembly information is written to the log.

OnShutdown stops every service (ServiceProvider.Stop) and flushes the log.

4Application services

IApplicationService, ApplicationService and ServiceProvider live in Kelly.Windows Hosting. The host collects every IApplicationService in its own assembly plus the two it creates itself, and starts them in ascending StartOrder behind a progress window. A service that doesn't report itself started isn't registered, and the first failure stops the loop. GetService<T>() resolves by exact type, base class or interface (for example IAutoUpdaterControl).

Add-in events

  • AutoUpdaterService.RunningChanged(bool) is raised after Suspend and Resume; Trade.All's Updater panel sets its power icon from it.
  • Ribbon combo box DropDownClosed (11 subscriptions in the modules, mostly the assigner combo boxes) goes to RibbonComboBoxEvents.RefillOnRefreshList in Kelly.Revit.UI, which refills the list on "Refresh List" and refreshes the active view.
  • Revit ExternalEvents are used only by Trade.Pipe's Olet Checker (SelectionExternalEventHandler, ConnectOletsExternalEventHandler) for its modeless window.

6Ribbon and modules

  • RibbonService calls RibbonModuleLoader.LoadModules (Kelly.Revit.UI), which loads Kelly.Revit.Trade.All.dll, .Pipe, .Duct, .Contenter, .Manager and .Developer from beside the add-in, in tab order. A missing file means no tab; a module that fails is reported and never stops startup.
  • Each module declares an IRibbonModule. Its CreateRibbon adds panels through RibbonPanelConfigurationBase subclasses, which add push, split, stacked and pull-down buttons and RibbonComboBox / ProjectRibbonComboBox items. Icons are embedded <ImageName>16.png and 32.png.
  • test/Tests.Revit/AddIn/AddInContractTests checks every module's commands, availability classes and buttons.

7Commands

The command framework is in Kelly.Revit.UI Commands:

  • CommandBase and IExternalCommandBase are the base of the commands; InitializeCommand captures the ExternalCommandData (UI application, document).
  • CommandRunner runs a command's work and maps the outcome to a CommandResult: Escape gives Cancelled; ErrorMessageException or any other exception gives Failed with the message. ToResult turns it into Revit's Result.
  • IExternalCommandMvvm with MvvmDialog.Show is the MVVM tool pattern: create and validate the view model and view, show the view modally, dispose. Base types are in Mvvm; shared XAML in Resources and Controls (DialogFooter, DialogMenu, ScopeControl, ElementControl). Views and view models stay in Kelly-Revit.
  • Availability: DocumentCommandAvailability (needs an active document), SelectionMadeCommandAvailability and DocumentHasElementsOfTypeCommandAvailability; each module's availability classes derive from these.
  • Selection filters and scope helpers live in Selection and Scope (UiDocumentScopeExtensions, ScopeSourceExtensions).

8Transactions

Kelly.Revit.Logic Operations/OperationService wraps a Revit Transaction or TransactionGroup (TransactionKind, TransactionName) with timing (StopWatchState) and an operation log (OperationServiceLogRecord) under C:\Projects\Revit\<document title>. Stop commits or assimilates, and IsCommitted is true only when the change actually reached the document. Moving the remaining call sites to OperationService.Run is parked work.

9Updaters

All in Kelly.Revit.Logic Updaters.

  • Auto updaters. AutoUpdaterManager creates one AutoUpdater (IUpdater) per IAutoUpdaterConfiguration: 19 in Configurations/Auto (bill of material type, checkbox defaults, content identity, detailing package, detailing phase, end preparation, fabrication part instances, field trim, layout discipline, line number, material, schedule gauge, service for fabrication and non-fabrication parts, size, suspended support, system, weld). They are built per document on open, bound to the document's element service and trigger filter, and run in the service's execution order.
  • Element services. ElementService (base of IElementService) holds each configuration's elements, filter and processing loop; ElementDataModels read and write the Kelly parameters.
  • Manual updaters. ManualUpdaterRunner suspends the auto updaters, runs each of the 15 manual configurations (ManualUpdaterConfigurationSet) over a scope (document, view or selection), each in its own operation with a progress window, and always resumes. Used by Trade.All's manual updater commands and the Spool Manager.
  • Fabrication custom data. CustomDataUpdater and CustomDataUpdateEvaluator write data-file values into fabrication part custom data, for Contenter's updater commands.
  • Suspend and resume points: sync with central, manual runs, and the Updater power button.

10Data and caches

  • Data files. DataFileService and DataFileLoader read CSV only, checked against manifest.json (SHA-256 and row counts). Reload Data (Trade.All, Updater panel) uses the same loader; an older export loads only if the user agrees.
  • Application caches. ComponentCache, ExternalParameterDefinitionCache (with CacheByDefinitionName), ProductCache, ProductRangeCache, ServiceCache, SystemCache and TerminologyCache, reached through App.Caches and the DataFiles seam.
  • Document caches. DocumentCache and IDocumentCache with ServiceDocumentCache, SystemDocumentCache, NumberedDocumentCache (line, module and spool numbers) and DetailingPackageDocumentCache; they feed the assigner combo boxes.

11Cross-cutting

  • Logging. Serilog through LoggerServices writes the application log; EventHandlerTools writes event names to the development log.
  • Errors. ExceptionExtensions.HandleIt (Kelly.Windows) logs and shows a "JH Kelly Exception Handler" prompt through UserPrompt; ErrorMessageException carries a user-facing message to CommandRunner.
  • Progress. ProgressBarService (Kelly.Windows Wpf) for service start-up, updater builds and manual runs.
  • Install. Kelly-Revit-v5 builds don't install unless -p:InstallAddin=true. V5 installs to C:\Program Files\JH Kelly\Kelly Tools For Revit\V5\<year> with the manifest Kelly Tools For Revit 5.addin; the version installed last is the active one in a Revit year.
