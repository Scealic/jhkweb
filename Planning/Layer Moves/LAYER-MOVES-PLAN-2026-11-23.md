## Decisions needed

1. **Prompts (P1b, 21 records).** Replace every direct `TaskDialog.Show` with `UserPrompt`. The dialogs look the same (title prefix on, no icon), but a call that sets an option `PromptRequest` lacks (such as a footer, KTR5-4765) stays as it is. *Recommendation: include, and leave any call `PromptRequest` cannot express.*
2. **Upward moves from Kelly-Revit-UI into the modules (#138 to #147).** Ten files only one module uses (`ConnectorPickTools`, five selection filters, `FamilySymbolWrapper`, `TitleBlockExtensions`, the two combo-box item models and their builders). Public types leave Kelly-Revit-UI, a breaking change there, and their UI tests move to `Tests.Revit`. *Recommendation: include.*
3. **Settings models back to Kelly-Revit (#148, #149).** `ModuleCreatorSettings` and `SpoolCreatorSettings` are models a view model fills (rule 2), moved down to Kelly-Domain before 2026-11-06. The types move up; their rules (`FromModuleNumber`, `GetModuleNumber`, `IsExistingPrefixOptionSelected`) stay in Kelly-Domain as a static tool. The JSON property names stay, so saved files still read. *Recommendation: include.*
4. **Arrangement arithmetic (#29, #31, medium).** About 90 lines of 2D align and distribute arithmetic leave `AnnotationArranger`, and the public `ArrangeAction` enum moves from Kelly-Revit-Logic to Kelly-Windows (breaking for Logic). *Recommendation: include; the arithmetic gets tests outside Revit for the first time.*

The other medium-risk moves (#111 `RunAsOneEdit`, #118, #120 and #121 in the Assigner pane) are member extractions of Revit transactions; they keep the transaction names and order exactly.

## Kept on purpose

- The host (`App`, `EventService`, `RibbonService`, `ApplicationSessionService`): already thin; everything left uses host statics or Revit events.
- The Arrange commands' pick-if-empty orchestration (`Arranger`): only one tool uses it.
- `ViciousFileBasedSystemPipePlaceTools`: ExcelDataReader stays in Kelly-Revit.
- Availability classes and push buttons: they stay beside their commands (rule 4).

## Rules baseline

`check-rules.pl` before any change: 0 Revit API hits in the Revit-free layers, 0 upward dependencies, 0 protected files outside Kelly-Revit (9 approved exceptions), 0 namespace mismatches. Every layer builds with 0 errors (the Kelly-Revit host and Trade.All checked in 2024).

## Implementation order

Bottom-up, each step repinned on the package the step below packs:

1. **Kelly-Windows-v3**: P1a, P1c, P1d, P1e (targets) and the Windows-internal source edits (#63, #74, #75, #78).
2. **Kelly-Domain**: repin; the Domain source package (guards, identifier preambles, feet to inches, `ScopeTypeExtensions` deleted, the two settings types removed); P2a, P2b.
3. **Kelly-Revit-Logic-v5**: repin; the Logic source package (guards, literals, `TaskDialogSimple`, rules now in Domain); P3a, P3b.
4. **Kelly-Revit-UI**: repin; the UI source package (guards, status colours, prompts, the ten files that move up removed).
5. **Kelly-Revit-v5**: repin; P5a first (receives the upward files), then the source packages per module (prompts, text, Assigner pane, tools). All 21 configurations build.

Kelly-Windows-Data has no moves and is not repinned. The in-Revit tests of Logic, UI and Kelly-Revit run in Revit 2024 through `revit-test.sh` when Revit is closed and licensed; otherwise they are compiled only.
