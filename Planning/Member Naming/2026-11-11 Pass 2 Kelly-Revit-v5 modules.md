# Member naming check, pass 2: Kelly-Revit-v5 modules (2026-11-11)
Second pass after the first-pass renames landed (commit `9bcfb10e`, KTR5-4804 to KTR5-4808). Sources: groups G14, G15, G16, G17. Readers: Sonnet; checked by: Opus.

Paths are relative to `Kelly-Revit-v5/modules`. "Shown" marks text a user sees (button text, column header, dialog text, ribbon item name). A push button's ribbon item name is its class name split into words (`RibbonPushButton.ItemName`), so renaming a push button type changes a **Serialized** id: Revit keyboard shortcuts and Quick Access Toolbar entries that point at the old item name stop working. Several first-pass items were not applied by `9bcfb10e`; they are marked "(first pass, not applied)".

## Summary
- Confirmed: **16 Misleading**, **63 Vague**, **28 Style** (counted per table row; several rows batch small items).
- Possible bugs: **8 confirmed**, **16 dropped** (unreachable, documented, dead code rather than a defect, or already filed).
- Findings on Logic and Domain members (`PathExtensions.Get*Directory`, `ArrangerOrientation`, `ValveClearanceSphereTools`, `HangerPlaceSettings`, `HangerSpacing`, `MaterialTools.RemoveMaterialsFromFamily`, `ExportKellyBindingsMarkdownReport`) are left to the Logic and Domain reviewers.
- Nine rename issues proposed (R1 to R9), each about 2 points, in KTR5 with feature label "Add-In Wide" unless one tool dominates.
